# Yokodori 0.1.0

## Summary

0.1.0 is the first public Yokodori SDK release. It establishes deterministic initial model-context compilation and passive observation of Pi's supported full-context boundary without making Yokodori the authority for repository truth, process execution, AgentRun lifecycle, orchestration, or provider transport.

## Package

- npm package: https://www.npmjs.com/package/yokodori
- npm registry: https://registry.npmjs.org/
- repository: https://github.com/yohn-jp/yokodori

Install after publication:

```bash
npm install yokodori@0.1.0
```

## Public API

The release exposes only:

- `yokodori` — deterministic initial-context compiler, runtime, typed context contracts, and outbound snapshots.
- `yokodori/pi` — the Pi adapter and attachment status/error contracts.

There is no Yokodori CLI or daemon in 0.1.0.

## Highlights

- Deterministic canonical initial-context rendering with stable section ordering and SHA-256 digests.
- Duplicate source identities fail deterministically.
- Pi integration through supported `before_agent_start` and `context_with_system` extension boundaries.
- `control`, `append`, and explicit experimental `replace` initial-context modes.
- Passive outbound observation with per-request sequence, normalized transcript structure, digest, statistics, completeness, and fidelity metadata.
- Explicit fidelity reporting for Pi's post-`context_with_system` forced-system-prompt projection in replace mode.
- Strict observation certification can become uncertifiable without mutating or cancelling the Pi provider request.
- Machine-enforced package and Pi-import boundaries.

## Verification basis

Implementation #1 proves the initial vertical slice with deterministic compiler fixtures and a native fake provider traversing Pi's real session, resource-loader, extension-runner, and model-runtime path.

The release preparation must pass the repository's current `npm run verify` and organization-managed CI before publication. Publication itself is a separate release operation and is not implied by this document.

## Known boundaries

0.1.0 does not implement semantic compression, canonical cognitive state, evidence paging, Hachidori/Clef integration, semantic probes, metacognition, reasoning forks, human-output forks, Tsukai production integration, Mottainai integration, provider-wire capture, a CLI, or a daemon.

Control and append snapshots conservatively do not claim universal provider-effective fidelity because Pi may apply later request projections beyond the supported observation boundary.

## Compatibility

- Node.js 22 or later.
- Pi coding-agent integration is implemented and tested against `@earendil-works/pi-coding-agent@1.0.2`.

## Breaking changes

None. This is the initial public release.
